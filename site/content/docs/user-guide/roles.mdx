---
title: Roles and permissions
description: The seven predefined OrkStage roles (three for the platform, four per tenant), what each can do, and how every request enforces tenant isolation.
---

OrkStage has seven predefined roles. **Platform roles** apply to the whole installation. **Tenant
roles** apply per tenant, so one user can be an admin in one tenant and a viewer in another.

## Platform roles

| Role | Can |
|---|---|
| `PlatformOwner` | Everything, including global settings. |
| `PlatformAdmin` | Everything except changing global settings (it can read them) and deleting the organization. Manages cloud targets, templates and tenants. |
| `PlatformOperator` | Read everything except settings. Deploy, restart, scale and approve instances. Create and update incidents, and update status pages. Cannot manage cloud targets, publish templates or destroy instances. |

## Tenant roles

| Capability | Owner | Admin | Developer | Viewer |
|---|:-:|:-:|:-:|:-:|
| Read instances, deployments, services, incidents, status page, notifications | ✓ | ✓ | ✓ | ✓ |
| Read templates, plans, applications | ✓ | ✓ | ✓ | ✓ |
| Deploy and restart instances | ✓ | ✓ | ✓ | |
| Import IaC | ✓ | ✓ | ✓ | |
| Create, update, scale, destroy and approve instances | ✓ | ✓ | | |
| Read members and the audit log | ✓ | ✓ | | |
| Manage API keys and webhooks | ✓ | ✓ | | |
| Manage members, update the tenant | ✓ | | | |

Tenant roles never get access to cloud targets, settings or template publishing.

## How it is enforced

1. The request is authenticated with a session cookie or an [API key](/docs/developer/api-keys/).
2. Queries for records that belong to a tenant are filtered by the caller's memberships.
3. Every loaded record is checked against the same rules (CASL) before any action.
4. The action is written to the audit log.

A request for another tenant's record gets **404**, not 403, so the response does not reveal that
the record exists. The console receives the rules from `GET /me` only to hide what you cannot do.
The API remains the authority.

## API keys and roles

An API key acts **with a role**. A tenant key uses `CustomerAdmin`, `CustomerDeveloper` or
`CustomerViewer`. A key for the whole organization uses `PlatformAdmin` or `PlatformOperator`.
Scopes then narrow what the role allows, so a key can never do more than its role.
