---
title: Troubleshooting
description: Fix common OrkStage problems. Startup configuration errors, ports in use, MiniStack and the Docker socket, OpenTofu runner containers, state buckets, permissions, busy instances, webhooks and imports.
---

Start with the **correlation id**: every API error and every deployment carries one. Search the API
and worker logs for it.

<Accordions type="multiple">
<Accordion title="The API or worker exits at startup with &quot;Invalid configuration&quot;">

Configuration is validated at startup and every problem is listed, for example
`SESSION_SECRET: Too small` or `ENCRYPTION_KEY: Set ENCRYPTION_KEY (32 bytes, base64) in production.`
Fix the variables named; see the [configuration reference](/docs/self-hosting/configuration/). In
production the dev login, private webhooks, a missing `ENCRYPTION_KEY` and a `change-me` session secret
are refused on purpose.

</Accordion>
<Accordion title="docker compose fails with &quot;port is already allocated&quot;">

The stack publishes `3000`, `4000`, `4566`, `5432`, `6379`, `1025` and `8025`. Stop the process using
the port (often a local Postgres or Redis) or change the left side of the port mapping in
`infra/local/docker-compose.yml`, and update `WEB_PUBLIC_URL`/`API_PUBLIC_URL` if you move 3000 or
4000.

</Accordion>
<Accordion title="MiniStack does not start, or RDS / ECS containers never appear">

MiniStack needs the Docker socket (`/var/run/docker.sock`) to start real containers. On Docker
Desktop, enable the default socket; with rootless Docker or Podman, mount the matching socket path.
Containers it starts join `cloud-orchestrator_default`; if you renamed the compose project, update
`DOCKER_NETWORK` for MiniStack and `TOFU_DOCKER_NETWORK` for the worker. Check
`docker compose … logs ministack`.

</Accordion>
<Accordion title="Target validation: &quot;State bucket … is not accessible&quot;">

On real AWS the state bucket must exist before the first deployment, versioned and encrypted, named
`orkstage-tfstate-<account>-<region>` or set as `stateBucket` on the target. On MiniStack it is
created automatically, so this error there usually means the emulator is not running or
`endpointUrl` is wrong. See [Connecting an AWS account](/docs/self-hosting/connect-aws/).

</Accordion>
<Accordion title="Deployment fails in the targets phase with AUTHORIZATION_ERROR">

The deployment role lacks actions the deployed services need; the event log names them. Update the
role from the current `infra/aws/orkstage-deployment-role.yaml` and validate the target again. If the
check says it was skipped, the role is missing `iam:SimulatePrincipalPolicy` on itself.

</Accordion>
<Accordion title="Resources fail with &quot;Cannot connect to the Docker daemon&quot; or runners hang">

The worker starts OpenTofu runners through the Docker socket. In compose it runs as root for that
reason. Check that the socket is mounted into the worker, that `TOFU_WORK_VOLUME` and
`TOFU_PLUGIN_CACHE_VOLUME` volumes exist (`docker volume ls | grep orkstage-tofu`), and that the
runner image is built (`docker compose … build tofu-runner`). A command is killed after
`TOFU_TIMEOUT_MINUTES`.

</Accordion>
<Accordion title="&quot;409 INSTANCE_BUSY&quot; when deploying">

Only one operation runs per instance. Wait for the current deployment (or cancel it), then deploy
again. A deployment parked in `AWAITING_APPROVAL` also keeps the instance busy until it is approved
or cancelled.

</Accordion>
<Accordion title="Verification says &quot;Resource no longer exists at the provider&quot;">

Someone deleted the resource outside OrkStage. Deploy again: the missing resource is re-created.

</Accordion>
<Accordion title="Webhook creation fails with UNSAFE_WEBHOOK_URL">

Webhook URLs must be `https://` and resolve to public addresses. For a receiver on your machine
during development, set `WEBHOOK_ALLOW_PRIVATE=true` (development only), or use a tunnel with a
public HTTPS URL.

</Accordion>
<Accordion title="Import upload answers 501 SCANNER_UNAVAILABLE">

The server does not have the WebAssembly scan engine installed. Scan locally with `ork import`
(Preview) and send the report, or install `@orkstage/scan` with the API.

</Accordion>
<Accordion title="The console shows &quot;The console could not load your session&quot;">

The console reaches the API through its own origin. Check `API_INTERNAL_URL` (set at the console's
build time) and that the API answers `GET /api/v1/readyz`. Sessions expire after 12 hours; sign in
again.

</Accordion>
</Accordions>
