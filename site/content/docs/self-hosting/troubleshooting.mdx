---
title: Troubleshooting
description: Fixes for common OrkStage problems, from startup configuration errors and busy ports to MiniStack, OpenTofu runners, state buckets, permissions and webhooks.
---

Start with the **correlation id**. Every API error and every deployment carries one. Search the API
and worker logs for it.

## Common problems

<Accordions type="multiple">
<Accordion title="The API or worker exits at startup with &quot;Invalid configuration&quot;">

OrkStage validates its configuration at startup and lists every problem, for example
`SESSION_SECRET: Too small: expected string to have >=32 characters` or `ENCRYPTION_KEY: Set ENCRYPTION_KEY (32 bytes, base64) in production.`
Fix the variables it names (see the [configuration reference](/docs/self-hosting/configuration/)).

In production, OrkStage refuses on purpose to start with the dev login, private webhooks, a missing
`ENCRYPTION_KEY` or a session secret that starts with `change-me`.

</Accordion>
<Accordion title="docker compose fails with &quot;port is already allocated&quot;">

The stack publishes ports `3000`, `4000`, `4566`, `5432`, `6379`, `1025` and `8025`. Stop the process
that holds the port (often a local Postgres or Redis), or change the left side of the port mapping in
`infra/local/docker-compose.yml`. If you move `3000` or `4000`, update `WEB_PUBLIC_URL` or
`API_PUBLIC_URL` to match.

</Accordion>
<Accordion title="MiniStack does not start, or RDS and ECS containers never appear">

MiniStack needs the Docker socket (`/var/run/docker.sock`) to start real containers. On Docker
Desktop, enable the default socket. With rootless Docker or Podman, mount the matching socket path.

The containers MiniStack starts join the `cloud-orchestrator_default` network. If you renamed the
Compose project, update `DOCKER_NETWORK` for MiniStack and `TOFU_DOCKER_NETWORK` for the worker.
Check the logs with `docker compose -f infra/local/docker-compose.yml logs ministack`.

</Accordion>
<Accordion title="Target validation reports the state bucket as not accessible">

On real AWS, the state bucket must exist before the first deployment, with versioning and
encryption. Its name is `orkstage-tfstate-<account>-<region>`, or the name set in `stateBucket` on
the target.

On MiniStack, OrkStage creates the bucket on first use. A state bucket error there usually means the
emulator is not running or the endpoint is wrong (`endpointUrl` on the target, or
`AWS_EMULATOR_ENDPOINT`). See [Connecting an AWS account](/docs/self-hosting/connect-aws/).

</Accordion>
<Accordion title="Deployment fails in the targets phase with AUTHORIZATION_ERROR">

The deployment role lacks actions that the deployed services need, and the event log names them.
Update the role from the current `infra/aws/orkstage-deployment-role.yaml`, then validate the target
again. If the check reports that it was skipped, the role is missing `iam:SimulatePrincipalPolicy`
on itself.

</Accordion>
<Accordion title="Resources fail with &quot;Cannot connect to the Docker daemon&quot;, or runners hang">

The worker starts OpenTofu runners through the Docker socket, which is why it runs as root in
Compose. Check that:

- the socket is mounted into the worker;
- the `TOFU_WORK_VOLUME` and `TOFU_PLUGIN_CACHE_VOLUME` volumes exist
  (`docker volume ls | grep orkstage-tofu`);
- the runner image is built
  (`docker compose -f infra/local/docker-compose.yml --profile platform build tofu-runner`).

OrkStage kills a command that runs longer than `TOFU_TIMEOUT_MINUTES`.

</Accordion>
<Accordion title="Deploying returns &quot;409 INSTANCE_BUSY&quot;">

Only one operation runs on an instance at a time. Wait for the current deployment to finish, or
cancel it, then deploy again. A deployment parked in `AWAITING_APPROVAL` also keeps the instance busy
until someone approves or cancels it.

</Accordion>
<Accordion title="Verification says &quot;Resource no longer exists at the provider&quot;">

Someone deleted the resource outside OrkStage. Deploy again, and OrkStage recreates the missing
resource.

</Accordion>
<Accordion title="Webhook creation fails with UNSAFE_WEBHOOK_URL">

Webhook URLs must use `https://` and resolve to public addresses. To test with a receiver on your own
machine, set `WEBHOOK_ALLOW_PRIVATE=true` (development only), or use a tunnel with a public HTTPS URL.

</Accordion>
<Accordion title="Import upload returns 501 SCANNER_UNAVAILABLE">

The server does not have the WebAssembly scan engine installed. Scan on your machine with
`ork import` (Preview) and send the report, or install `@orkstage/scan` with the API.

</Accordion>
<Accordion title="The console shows &quot;The console could not load your session&quot;">

The console reaches the API through its own origin. Check `API_INTERNAL_URL`, which is set when the
console is built, and check that the API answers `GET /api/v1/readyz`. Sessions expire after 12
hours, so you may only need to sign in again.

</Accordion>
</Accordions>
