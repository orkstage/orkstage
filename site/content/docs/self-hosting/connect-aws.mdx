---
title: Connecting an AWS account
description: Connect a real AWS account to OrkStage. Create the deployment role with the CloudFormation template and an external id, prepare the OpenTofu state bucket, register and validate the cloud target, and understand the permission checks.
---

OrkStage never stores AWS keys for your accounts. The worker assumes a **deployment role** in each
account with **AssumeRole + an external id** and gets short-lived credentials (one hour, cached in
memory, never persisted or logged).

```text
control plane identity (worker task role / IAM user)
      │  sts:AssumeRole  + ExternalId
      ▼
co-deploy role in the customer account  ──▶  OpenTofu runner (credentials for that one container)
```

<Callout type="warn">
  Prefer a dedicated AWS account per environment: the deployment role can create and delete
  infrastructure.
</Callout>

<Steps>
<Step>

### Create the deployment role

Launch the CloudFormation template `infra/aws/orkstage-deployment-role.yaml` (from the platform
repository) once in each account you connect.

| Parameter | Value |
|---|---|
| `ControlPlanePrincipalArn` | ARN of the identity the OrkStage worker runs as, e.g. `arn:aws:iam::111122223333:role/orkstage-worker` |
| `ExternalId` | A random shared secret, at least 16 characters (`openssl rand -hex 24`). `NoEcho`. |
| `RoleName` | Default `co-deploy` |

```bash
aws cloudformation deploy \
  --stack-name orkstage-deployment-role \
  --template-file infra/aws/orkstage-deployment-role.yaml \
  --capabilities CAPABILITY_NAMED_IAM \
  --parameter-overrides \
      ControlPlanePrincipalArn=arn:aws:iam::111122223333:role/orkstage-worker \
      ExternalId="$EXTERNAL_ID"
```

The stack outputs **`RoleArn`** and **`AccountId`**; you paste both into the cloud target.

What the role may do, in short:

- manage EC2/VPC, ECS, RDS, ElastiCache, ELB, Auto Scaling, Route 53 and ACM resources;
- manage ECR repositories, SQS queues, Secrets Manager secrets, S3 buckets and IAM service roles
  whose names start with `co-` (every physical name OrkStage creates does), and log groups under
  `/orkstage/`;
- read and write the OpenTofu state bucket `orkstage-tfstate-<account>-*`;
- pass `co-*` roles only to ECS tasks and EC2;
- call `iam:SimulatePrincipalPolicy` **on itself**, so OrkStage can check permissions before it
  deploys.

The template is kept in sync with the actions the OpenTofu modules need; a platform unit test fails
when a module needs an action the policy does not grant.

</Step>
<Step>

### Store the external id

Put the external id in a secret store the control plane can read and reference it, never paste the
value:

```text
aws-sm://orkstage/aws/prod-external-id          # AWS Secrets Manager (name or ARN, optional #jsonKey)
env://ORKSTAGE_AWS_PROD_EXTERNAL_ID             # environment variable of the API and worker
```

See [Secret references](/docs/self-hosting/secrets/).

</Step>
<Step>

### Prepare the state bucket

OpenTofu state lives in S3, one state file per resource (`orkstage/<physical-name>.tfstate`). On a
real account the bucket must exist before the first deployment:

- default name `orkstage-tfstate-<accountId>-<region>`, or set `stateBucket` on the target;
- **versioning enabled** (recover from a damaged state);
- **default encryption** enabled;
- public access blocked;
- locking uses OpenTofu's S3-native lock file (`use_lockfile`), so no DynamoDB table is needed.

```bash
B=orkstage-tfstate-123456789012-us-east-1
aws s3api create-bucket --bucket "$B" --region us-east-1
aws s3api put-bucket-versioning --bucket "$B" --versioning-configuration Status=Enabled
aws s3api put-bucket-encryption --bucket "$B" \
  --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
aws s3api put-public-access-block --bucket "$B" \
  --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

</Step>
<Step>

### Register the cloud target

**Cloud targets → Register cloud target** (platform owners and admins), or the API:

```http
POST /api/v1/cloud/targets
Content-Type: application/json

{
  "provider": "aws",
  "name": "aws-prod",
  "environment": "production",
  "config": {
    "accountId": "123456789012",
    "roleArn": "arn:aws:iam::123456789012:role/co-deploy",
    "stateBucket": "orkstage-tfstate-123456789012-us-east-1",
    "dnsZone": "apps.example.com"
  },
  "credentialRef": "aws-sm://orkstage/aws/prod-external-id",
  "allowedRegions": ["us-east-1", "eu-west-1"],
  "defaultRegion": "us-east-1",
  "maxConcurrentDeployments": 3
}
```

| `config` field | Meaning |
|---|---|
| `accountId` | 12-digit account id (the `AccountId` output). |
| `roleArn` | The `RoleArn` output. |
| `stateBucket` | Optional; defaults to `orkstage-tfstate-<accountId>-<region>`. |
| `dnsZone` | Platform DNS zone for instance subdomains, pre-provisioned in Route 53. |
| `ecsAmiId` | Optional AMI for `ecs-ec2` capacity; empty uses the latest ECS-optimized AMI from SSM. |

`config` must not contain secrets: the API rejects keys that look like secrets
(`422 SECRET_IN_CONFIG`). `credentialRef` must be an `env://` or `aws-sm://` reference; any other
value is rejected. A target can be assigned to one tenant (`tenantId`) or shared.

</Step>
<Step>

### Validate

Click **Validate** (or `POST /cloud/targets/:id/validate { "region": "us-east-1" }`). OrkStage:

1. resolves the external id and **assumes the role**;
2. checks that the credentials belong to `accountId`;
3. checks the **state bucket** is reachable;
4. **simulates the role** against the actions each supported service needs
   (`iam:SimulatePrincipalPolicy`).

Missing actions for a service show up as **warnings** on the Validate button: a target may be scoped
to fewer services on purpose. If the role cannot call `iam:SimulatePrincipalPolicy`, the permission
check is reported as skipped.

</Step>
</Steps>

## During a deployment

The **Validate cloud targets** phase repeats the checks for each target and region the deployment
uses, this time strictly for the services being deployed: a missing permission fails the phase with
`AUTHORIZATION_ERROR` before any resource is touched, naming the missing actions.

## What OrkStage creates in your account

| Template resource | AWS resources |
|---|---|
| `network` | VPC, public/private subnets, internet gateway, route tables, internal security group, optional NAT gateways |
| `container-registry` | ECR repository, lifecycle policy |
| `compute.container-service` | ECS cluster, task definition, service, log group, execution role, security group; EC2 launch template, Auto Scaling group and capacity provider for `ecs-ec2`; Application Auto Scaling for `autoscaling` |
| `database.postgresql` | RDS PostgreSQL instance, subnet group, security group, Secrets Manager secret (password generated as an ephemeral value, written write-only) |
| `cache.redis` | ElastiCache Valkey replication group, subnet group, security group |
| `queue` | SQS queue and dead-letter queue |
| `object-storage` | S3 bucket with public access block, encryption, versioning and lifecycle |
| `ingress` | Application Load Balancer, target groups, HTTP listener and rules |
| `dns` | Route 53 record, ACM certificate with DNS validation, HTTPS listener |

Every resource carries the platform's standard tags and a `co-<tenant>-<instance>-<resource>` name.
