---
title: Secret references
description: How OrkStage handles secrets. References instead of values, the env:// and aws-sm:// schemes, AWS Secrets Manager with JSON keys, emulator settings, and where secrets never appear.
---

OrkStage stores **references** to secrets, never their values, and resolves them at the moment of
use. Values are not written to the database, not returned by the API and not logged.

## Schemes

| Reference | Resolved from |
|---|---|
| `env://NAME` | An environment variable of the API and worker processes. `NAME` is uppercase letters, digits and `_`. Good for local development and simple installs. |
| `aws-sm://<name-or-arn>` | The `SecretString` of an AWS Secrets Manager secret. |
| `aws-sm://<name-or-arn>#<jsonKey>` | One string field of a JSON secret. |

```text
env://ORKSTAGE_AWS_PROD_EXTERNAL_ID
aws-sm://orkstage/aws/prod-external-id
aws-sm://arn:aws:secretsmanager:eu-west-1:111122223333:secret:orkstage/targets-AbCdEf#prodExternalId
```

Cloud target `credentialRef` values must use one of these schemes; the API rejects anything else,
including a pasted secret value.

## AWS Secrets Manager

`aws-sm://` secrets are read with the **control plane's own AWS credentials**, through the default
provider chain (ECS task role, EC2 instance profile, SSO, environment), not with a customer's
deployment role.

| Setting | Default | Meaning |
|---|---|---|
| `SECRETS_AWS_REGION` | `us-east-1` | Region for references by name. ARNs carry their own region. |
| `SECRETS_AWS_ENDPOINT` | | Endpoint override for emulators (e.g. MiniStack), as reachable from the API and worker. |

The control plane identity needs `secretsmanager:GetSecretValue` on the referenced secrets (and
`kms:Decrypt` if they use a customer-managed key). Values are cached in memory for five minutes so a
deployment with many references does not hit rate limits. Error messages name the secret in redacted
form and keep only the error class, because SDK messages can include account ids.

## What else counts as a secret

| Secret | Where it lives |
|---|---|
| `SESSION_SECRET`, `ENCRYPTION_KEY`, `ORKSTAGE_LICENSE_KEY`, OIDC client secrets | Environment of the API and worker; inject them from your secret store. |
| Webhook signing secrets (`whsec_…`) | Database, encrypted with `ENCRYPTION_KEY`; shown once at creation or rotation. |
| API key tokens | Only their SHA-256 is stored; shown once at creation. |
| Database passwords of provisioned RDS instances | Generated by OpenTofu as an ephemeral value and written write-only to RDS and to a Secrets Manager secret in the customer account. **State holds `password: null`.** Services receive the secret's ARN. |
| AWS credentials for customer accounts | Never stored: short-lived AssumeRole credentials, in memory, passed to one runner container as environment variables. |

## Not yet

A resolver for other secret stores (Azure Key Vault, OCI Vault, HashiCorp Vault) arrives with the
corresponding adapters.
