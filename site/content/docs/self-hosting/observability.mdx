## Logs

The API and the worker write structured JSON logs (Pino) to stdout, with `service` and `context`
fields and the request's **correlation id**. Tokens, secrets, cookies and authorization headers are
redacted. Set the level with `LOG_LEVEL` (`info` by default).

```bash
docker compose -f infra/local/docker-compose.yml --profile platform logs -f api worker
```

A correlation id travels from the HTTP request (`x-correlation-id`) into the deployment, the OpenTofu
runs, audit events and webhook deliveries. Search your log store by it to follow one operation end to
end.

## Health endpoints

| Endpoint | Meaning |
|---|---|
| `GET /api/v1/healthz` | Liveness: the API process answers. |
| `GET /api/v1/readyz` | Readiness: Postgres and Redis are reachable. The compose health check uses it. |

## Operational data in the product

- **Deployments**: every step, its duration, attempts and failure class; the event log; the Gantt
  timeline.
- **Overview**: instances, deployments, failures and incidents with trends.
- **Audit log**: every change, filterable by tenant (`GET /audit`).
- **Webhook deliveries**: status, attempts and last error per endpoint.

## Metrics and tracing

| | Status |
|---|---|
| OpenTelemetry SDK in the API and worker (traces, metrics) | Planned |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Accepted by the configuration, not used yet |
| An OpenTelemetry collector for local testing | Available: `--profile observability` in the compose file prints received telemetry |
| Control-plane dashboards and SLO alerts | Planned |

Until then, alert on `readyz`, on container restarts, on `deployment.failed` webhooks and on error
rates in the logs.
