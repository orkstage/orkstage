title: Quickstart
description: Run the full OrkStage platform locally with Docker Compose, sign in with the development login and deploy your first instance in about ten minutes.
---

This guide runs everything in containers: the API, the worker, the console, Postgres, Redis, a mail
catcher, the OpenTofu runner image and MiniStack (a local AWS emulator). You need **only Docker**; no
cloud account, no Node.js on the host.

<Callout title="Local evaluation only" type="warn">
  The compose stack runs in `NODE_ENV=development`: the development login is on, cookies are not
  `Secure`, and the worker mounts the Docker socket to start OpenTofu containers. Do not expose it to
  a network. For production see [Docker Compose deployment](/docs/self-hosting/docker-compose/) and
  [Security hardening](/docs/self-hosting/security/).
</Callout>

## Requirements

- Docker Engine or Docker Desktop with Compose v2, about 6 GB of free memory for the full stack
  (MiniStack starts real containers for RDS, ElastiCache and ECS tasks).
- Free ports: `3000` (console), `4000` (API), `4566` (MiniStack), `5432` (Postgres), `6379` (Redis),
  `1025`/`8025` (Mailpit).

## Run the platform

<Steps>
<Step>

### Get the code

```bash
git clone https://github.com/orkstage/orkstage.git
cd orkstage
```

</Step>
<Step>

### Start the stack

```bash
docker compose -f infra/local/docker-compose.yml \
  --profile platform --profile aws-emulator up -d --build --wait
```

The first run builds two images: `orkstage/platform:local` (API, worker, console and the one-shot
`migrate` job share it) and `orkstage/tofu-runner:local` (OpenTofu 1.12.7 with the modules baked in).
`migrate` applies database migrations and loads idempotent demo data, then exits.

With pnpm installed, `pnpm platform:up` runs the same command.

</Step>
<Step>

### Open the console

| Service | URL |
|---|---|
| Console | http://localhost:3000 |
| Control API and OpenAPI UI | http://localhost:4000/api/docs |
| MiniStack (local AWS) | http://localhost:4566 |
| Mailpit (emails) | http://localhost:8025 |

Sign in with the **development login**. The seed creates three users:

| Email | Role |
|---|---|
| `admin@example.local` | Platform owner: everything, including cloud targets and settings |
| `operator@example.local` | Platform operator: deploys, approves, manages incidents |
| `customer@example.local` | Customer owner of the tenant *Acme Corp* |

</Step>
<Step>

### Deploy the reference instance

The seed registers simulated AWS, Azure and OCI targets and an instance called **Acme Production**,
built from the `multicloud-reference` template: the API on (simulated) AWS ECS Fargate behind an ALB
with ECR and Route 53, Postgres on (simulated) Azure Flexible Server, object storage on (simulated) OCI.

1. Open **Instances → Acme Production**.
2. Open the **Plan & cost** tab: the resolved resources grouped by provider, the policy results, the
   cross-cloud links and the approximate monthly cost.
3. Click **Deploy**. Acme Production is a `production` instance, so an approval step is part of the
   deployment; it is skipped with a reason when nothing high-risk is planned.
4. Follow the steps and the event log live, or open **Deployments** for the timeline.

</Step>
<Step>

### Try the operations loop

On a resource of a simulated instance, use **Simulate** to mark it unhealthy. Within a health tick
(30 seconds in the compose file) the instance degrades, an incident opens, an email arrives in
Mailpit and the private status page changes. Set the resource healthy again and the incident
resolves on its own.

</Step>
</Steps>

## Deploy real AWS resources locally

The seed also creates the target **Local AWS (MiniStack)** and the instance **Acme Staging (local
AWS)** from `starter-standard`: VPC, ECR, ALB, RDS Postgres, Valkey, SQS, two ECS Fargate services,
Route 53 and ACM. Deploying it runs OpenTofu for real against MiniStack. Continue with
[Local AWS with MiniStack](/docs/get-started/local-aws/).

## Logs, rebuilds and shutdown

```bash
# follow the platform services
docker compose -f infra/local/docker-compose.yml --profile platform --profile aws-emulator logs -f api worker web

# rebuild after code changes
docker compose -f infra/local/docker-compose.yml --profile platform build
docker compose -f infra/local/docker-compose.yml --profile platform --profile aws-emulator up -d

# stop (volumes are kept; add -v to wipe all data)
docker compose -f infra/local/docker-compose.yml --profile platform --profile aws-emulator down
```

## Alternative: run the apps on the host

For hot reload while developing, run only the infrastructure in Docker and the apps with Node.js 24
and pnpm 12:

```bash
cp .env.example .env
pnpm install
pnpm local:up                 # Postgres, Redis, Mailpit
pnpm build
pnpm db:deploy && pnpm db:seed
pnpm --filter @co/api start   # http://localhost:4000/api/docs
pnpm --filter @co/worker start
pnpm --filter @co/web dev     # http://localhost:3000
```

See [Development setup](/docs/contributing/development-setup/) for details.
