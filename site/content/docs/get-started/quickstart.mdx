title: Quickstart

This guide runs everything in containers: the API, the worker, the console, Postgres, Redis, a mail
catcher, the OpenTofu runner image and MiniStack (a local AWS emulator). **Docker is the only
requirement.** You need no cloud account and no Node.js on the host.

<Callout title="Local evaluation only" type="warn">
  The compose stack runs with `NODE_ENV=development`. The development login is on, cookies are not
  `Secure`, and the worker mounts the Docker socket to start OpenTofu containers. Do not expose this
  stack to a network. For production, see [Docker Compose deployment](/docs/self-hosting/docker-compose/)
  and [Security hardening](/docs/self-hosting/security/).
</Callout>

## Requirements

- Docker Engine or Docker Desktop with Compose v2, and about 6 GB of free memory for the full stack.
  MiniStack starts real containers for RDS, ElastiCache and ECS tasks.
- These free ports: `3000` (console), `4000` (API), `4566` (MiniStack), `5432` (Postgres), `6379`
  (Redis), `1025` and `8025` (Mailpit).

## Run the platform

<Steps>
<Step>

### Get the code

```bash
git clone https://github.com/orkstage/orkstage.git
cd orkstage
```

</Step>
<Step>

### Start the stack

```bash
docker compose -f infra/local/docker-compose.yml \
  --profile platform --profile aws-emulator up -d --build --wait
```

The first run builds two images:

- `orkstage/platform:local`, shared by the API, the worker, the console and the `migrate` job.
- `orkstage/tofu-runner:local`, which contains OpenTofu 1.12.7 and the OpenTofu modules.

The `migrate` job runs once. It applies the database migrations, loads the demo data and exits. Running
it again is safe: the seed updates existing records instead of duplicating them.

If you have pnpm installed, `pnpm platform:up` runs the same command.

</Step>
<Step>

### Open the console

| Service | URL |
|---|---|
| Console | http://localhost:3000 |
| Control API and OpenAPI UI | http://localhost:4000/api/docs |
| MiniStack (local AWS) | http://localhost:4566 |
| Mailpit (emails) | http://localhost:8025 |

Sign in with the **development login**. The seed creates three users:

| Email | Role |
|---|---|
| `admin@example.local` | Platform owner: full access, including cloud targets and settings |
| `operator@example.local` | Platform operator: deploys, approves and manages incidents |
| `customer@example.local` | Customer owner of the tenant *Acme Corp* |

</Step>
<Step>

### Deploy the reference instance

The seed registers simulated AWS, Azure and OCI targets and an instance called **Acme Production**,
built from the `multicloud-reference` template. Its API runs on simulated AWS ECS Fargate behind an
ALB, with ECR and Route 53. Its Postgres database runs on simulated Azure Flexible Server, and its
object storage on simulated OCI.

1. Open **Instances**, then **Acme Production**.
2. Open the **Plan & cost** tab. It shows the resolved resources grouped by provider, the policy
   results, the links between clouds and the approximate monthly cost.
3. Click **Deploy**. Acme Production is a `production` instance, so the deployment includes an
   approval step. The step is skipped, with a recorded reason, when the plan has no high risk or
   destructive changes.
4. Follow the steps and the event log as they update, or open **Deployments** for the timeline.

</Step>
<Step>

### Try the operations loop

On a resource of a simulated instance, open **Simulate** and choose **Mark unhealthy**. Within one
health check interval (30 seconds in the compose file), the instance becomes degraded, an incident
opens, an email arrives in Mailpit and the private status page changes. Choose **Mark healthy** and
the incident resolves on its own.

</Step>
</Steps>

## Deploy real AWS resources locally

The seed also creates the target **Local AWS (MiniStack)** and the instance **Acme Staging (local
AWS)**, built from `starter-standard`. That instance contains a VPC, ECR, an ALB, RDS Postgres,
Valkey, SQS, two ECS Fargate services, Route 53 and ACM. Deploying it runs OpenTofu for real against
MiniStack. Continue with [Local AWS with MiniStack](/docs/get-started/local-aws/).

## Logs, rebuilds and shutdown

```bash
# follow the platform services
docker compose -f infra/local/docker-compose.yml --profile platform --profile aws-emulator logs -f api worker web

# rebuild after code changes
docker compose -f infra/local/docker-compose.yml --profile platform build
docker compose -f infra/local/docker-compose.yml --profile platform --profile aws-emulator up -d

# stop (volumes are kept; add -v to wipe all data)
docker compose -f infra/local/docker-compose.yml --profile platform --profile aws-emulator down
```

## Alternative: run the apps on the host

For hot reload during development, run only the infrastructure in Docker. Run the apps on the host
with Node.js 24 and pnpm 12:

```bash
cp .env.example .env
pnpm install
pnpm local:up                 # Postgres, Redis, Mailpit
pnpm build
pnpm db:deploy && pnpm db:seed
pnpm --filter @co/api start   # http://localhost:4000/api/docs
pnpm --filter @co/worker start
pnpm --filter @co/web dev     # http://localhost:3000
```

See [Development setup](/docs/contributing/development-setup/) for details.
