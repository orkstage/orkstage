OrkStage provisions and operates **isolated environments**, called *instances* (or *stages*), across
one or several clouds. An instance is a logical environment: services, a Postgres database, a cache,
a queue, object storage, ingress and DNS. **Each resource is placed independently**, so one instance
can run its API on AWS, its database on Azure and its storage on OCI.

The flow is always the same:

1. A provider-neutral **template** describes what the environment needs. Forged once, deployed many times.
2. An **instance** binds the template's placement slots to cloud targets and regions.
3. The **plan** resolves every resource, evaluates policies, estimates the monthly cost and chooses a
   connectivity strategy for links that cross clouds. Nothing touches a cloud yet.
4. A **deployment** applies the plan asynchronously as a dependency graph, with OpenTofu.
5. **Health checks** roll up to the instance, open **incidents**, feed a private **status page** and
   send **notifications**. Every change lands in an append-only **audit log**.

<Callout title="What is real today" type="warn">
  AWS resources are provisioned for real with OpenTofu, verified locally against
  [MiniStack](https://ministack.org) and usable against a real account through a cross-account role.
  **Azure and OCI are simulated** by a deterministic provider and labelled as simulated everywhere;
  their adapters are on the roadmap. The `ork` CLI is a <Badge>Preview</Badge>: it works against the
  API, but signed binaries are not released yet.
</Callout>

## Who it is for

- **Platform and DevOps teams** who run the same environment shape for many customers or teams, and
  want one reviewed, policy-checked path from template to cloud.
- **SREs** who need health, incidents, status and an audit trail tied to the infrastructure that was
  actually deployed.
- **Engineering managers** who approve production changes and want to see the plan, the risk and an
  approximate cost before anything is created.

## Open source

The core is licensed under the GNU **AGPL-3.0** and is complete on its own: you can self-host it and
run production workloads on AWS. Directories named `ee/` hold Enterprise features under a commercial
license, activated by an offline license key. See [Community vs Enterprise](/docs/enterprise/editions/).
