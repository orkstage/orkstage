OrkStage provisions and operates **isolated environments** on one or several clouds. Each
environment is called an *instance* (or a *stage*). It is a logical unit that groups services, a
Postgres database, a cache, a queue, object storage, ingress and DNS.

**OrkStage places each resource on its own.** One instance can run its API on AWS, its database on
Azure and its storage on OCI.

Every instance follows the same flow:

1. A **template** describes what the environment needs, without naming a provider. You write it
   once and deploy it many times.
2. An **instance** binds each placement slot of the template to a cloud target and a region.
3. The **plan** resolves every resource, evaluates policies, estimates the monthly cost and picks a
   connectivity strategy for each link between clouds. No cloud is touched at this step.
4. A **deployment** applies the plan in the background with OpenTofu, following the dependency graph.
5. **Health checks** roll up to the instance. They open **incidents**, update a private **status
   page** and send **notifications**. Every change is recorded in an **audit log** that only accepts
   inserts.

<Callout title="What works today" type="warn">
  OrkStage provisions real AWS resources with OpenTofu. We test this locally against
  [MiniStack](https://ministack.org), and it works on a real account through a role that OrkStage
  assumes in that account. **Azure and OCI are simulated** by a deterministic provider and labelled
  as simulated in every screen; real adapters are on the roadmap. The `ork` CLI is in
  <Badge>Preview</Badge>: it works against the API, but signed binaries are not released yet.
</Callout>

## Who it is for

- **Platform and DevOps teams** that run the same environment shape for many customers or teams.
  They get one reviewed path from template to cloud, with policy checks on every plan.
- **SREs** who need health, incidents, status and an audit trail tied to the infrastructure that
  was actually deployed.
- **Engineering managers** who approve production changes. They see the plan, the risk and an
  approximate cost before anything is created.

## Open source

The core is licensed under the GNU **AGPL-3.0** and is complete on its own. You can run it on your
own infrastructure and use it for production workloads on AWS. Directories named `ee/` hold
Enterprise features under a commercial license, which an offline license key turns on. See
[Community vs Enterprise](/docs/enterprise/editions/).
