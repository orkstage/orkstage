title: Local AWS with MiniStack
description: Provision real AWS resources with OpenTofu against MiniStack, a local AWS emulator that runs real containers for ECS, RDS and ElastiCache. No AWS account needed.
---

[MiniStack](https://ministack.org) is an MIT-licensed AWS emulator. Unlike pure API mocks it starts
real containers for ECS tasks, RDS and ElastiCache, so a deployment against it exercises the same
OpenTofu modules, the same state handling and the same health checks as a real account.

<Callout type="warn" title="Docker socket">
  MiniStack needs the Docker socket to start those containers, which gives it control of your Docker
  daemon. Use it on a development machine only.
</Callout>

## Start MiniStack

The [quickstart](/docs/get-started/quickstart/) compose command already includes the `aws-emulator`
profile. If you run the apps on the host instead:

```bash
pnpm local:aws    # docker compose ... --profile aws-emulator up -d --wait ministack
```

MiniStack listens on `http://localhost:4566`. Inside the compose network it is
`http://ministack:4566`; containers it starts join the same network.

## The seeded target

The seed registers an AWS cloud target named **Local AWS (MiniStack)**:

```json title="cloud target config"
{
  "accountId": "000000000000",
  "emulator": "ministack",
  "endpointUrl": "http://localhost:4566",
  "runnerEndpointUrl": "http://ministack:4566",
  "dnsZone": "orkstage.local",
  "createDnsZone": true
}
```

| Field | Meaning |
|---|---|
| `emulator` | Switches to the emulator's static test credentials and endpoint overrides. |
| `endpointUrl` | The AWS endpoint as reached by the API and worker processes. |
| `runnerEndpointUrl` | The same endpoint as reached from inside OpenTofu runner containers. |
| `dnsZone`, `createDnsZone` | Platform DNS zone for instance subdomains; created on first use on the emulator. |

In the compose stack the worker also sets `AWS_EMULATOR_ENDPOINT=http://ministack:4566`. Links shown
in the console keep `http://localhost:4566` so your browser can open them.

## Deploy Acme Staging

<Steps>
<Step>

### Validate the target

Open **Cloud targets → Local AWS (MiniStack)** and click **Validate**. Validation checks the
emulator credentials, account access and the OpenTofu state bucket (created and versioned on first
use on the emulator). It fails with a clear message when MiniStack is not running. The IAM permission
probe applies to real accounts only.

</Step>
<Step>

### Deploy

Open **Instances → Acme Staging (local AWS)** (template `starter-standard`) and click **Deploy**.
The worker runs one OpenTofu container per resource step, in dependency order, with one isolated
state file per resource in MiniStack's S3.

</Step>
<Step>

### Check what was created

| Template resource | AWS resources (OpenTofu module) |
|---|---|
| `network` | VPC, public and private subnets, internet gateway, route tables, internal security group (optional NAT gateway) |
| `registry` | ECR repository with scan on push, immutable tags and a lifecycle policy |
| `database` | RDS PostgreSQL instance, subnet group, security group, Secrets Manager secret for the credentials |
| `cache` | ElastiCache Valkey replication group, subnet group, security group |
| `messaging` | SQS queue with a dead-letter queue |
| `api`, `worker` | ECS cluster, task definition, service, CloudWatch log group, execution role, security group |
| `ingress` | Application Load Balancer, target groups, HTTP listener and path rules |
| `dns` | Route 53 record, ACM certificate with DNS validation, HTTPS listener |

The ALB is reachable through MiniStack at `http://localhost:4566/_alb/<lb-name>/`; the console shows
it as the ingress `url` output.

</Step>
</Steps>

## Mix real and simulated

You can bind only the `primary` slot of `multicloud-reference` to MiniStack and keep `data` (Azure)
and `storage` (OCI) on the simulated targets. The AWS part is provisioned for real, the rest is
simulated and labelled as such.

## Known differences from real AWS

- MiniStack reports in-place changes on a second plan for some RDS and ElastiCache attributes, so
  drift scans against the emulator can flag changes nobody made. Treat drift on MiniStack as a hint.
- Autoscaling is not emulated: services run their fixed `replicas` and the deployment logs a warning.
- MiniStack does not serve the public SSM parameter for the ECS-optimized AMI; `ecs-ec2` services use
  a placeholder AMI on the emulator.

## Contract tests against the emulator

```bash
MINISTACK_E2E=1 pnpm --filter @co/cloud-aws test
```

This runs the provider adapter contract suite (ensure, read, health, delete) against MiniStack.
