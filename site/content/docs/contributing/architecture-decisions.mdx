description: Summaries of the OrkStage architecture decision records. Placement slots, adapters and simulation, the BullMQ workflow engine, tenancy and authorization, OpenTofu execution and state, and toolchain choices.
---

Decisions are recorded as ADRs in `docs/adr/` of the platform repository. Each summary links to the
full record.

## 0001 Per-resource placement through template slots

**Accepted.** Templates are shared across tenants, but each tenant has its own accounts, so provider,
account and region cannot live in the template. Templates declare **placement slots** with allowed
providers; each resource names a slot; each instance binds slots to `{ targetId, region }`. The same
template becomes single-cloud or multi-cloud by binding alone, and networks bind only to resources in
the same slot. [Read ADR 0001](https://github.com/orkstage/orkstage/blob/main/docs/adr/0001-placement-slots.md)

## 0002 Provider adapters, capability catalogs and simulation

**Accepted.** `CloudProviderAdapter` is the only way the platform touches a cloud; `ensureResource`
converges to desired state so retries cannot duplicate. Logical resource → implementation mapping is
**data** (capability catalogs with features, regional gaps and static pricing). A deterministic `mock`
provider simulates AWS, Azure or OCI with injectable failures, and everything simulated is labelled.
A shared contract test suite runs against every adapter.
[Read ADR 0002](https://github.com/orkstage/orkstage/blob/main/docs/adr/0002-adapters-and-simulation.md)

## 0003 Deployment workflow on BullMQ with persisted steps

**Accepted.** Temporal would add a cluster to operate; BullMQ reuses the Redis and Postgres already
required. Jobs carry only the deployment id; steps are rows created at request time and updated
before and after each action; resume means re-running the job. Revisit Temporal if long human-in-the-loop
flows or very large fan-out appear.
[Read ADR 0003](https://github.com/orkstage/orkstage/blob/main/docs/adr/0003-workflow-engine.md)

## 0004 Tenancy, sessions and authorization

**Accepted.** Shared database with `tenantId` on every tenant-owned row, isolation in layers
(principal → query scoping → CASL on the loaded record → audit), foreign records reported as not
found. CASL rules are defined once and sent to the console for visibility only. Server-side opaque
sessions instead of JWTs. OIDC providers are configuration.
[Read ADR 0004](https://github.com/orkstage/orkstage/blob/main/docs/adr/0004-tenancy-and-authorization.md)

## 0005 OpenTofu execution and state

**Accepted.** Every `tofu` command runs in a pinned throwaway container with credentials only in its
environment. **One state per resource** in S3 with `use_lockfile` locking and encryption, keeping the
platform's DAG and per-resource failure isolation. No secrets in state (ephemeral passwords,
write-only attributes). The same code serves real AWS and MiniStack.
[Read ADR 0005](https://github.com/orkstage/orkstage/blob/main/docs/adr/0005-opentofu-state.md)

## 0006 Toolchain choices

**Accepted.** pnpm workspaces without Turborepo (machines block native binaries from `node_modules`);
TypeScript 7; Prisma 7.10 rather than a release candidate; Zod 4 shared by validation, OpenAPI and
forms; ESM everywhere.
[Read ADR 0006](https://github.com/orkstage/orkstage/blob/main/docs/adr/0006-toolchain.md)

## Writing a new ADR

Copy the structure of an existing record: **Status**, **Context**, **Decision**, **Consequences**.
Number it sequentially, keep it short, and supersede rather than rewrite an accepted decision.
