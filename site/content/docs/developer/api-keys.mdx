API keys authenticate automation: CI pipelines, scripts and the `ork` CLI. Each key acts with a
**role**, and its **scopes** narrow what that role allows. A key can never do more than its role,
and no key can manage other keys.

## Token format

```text
ork_<env>_<prefix>_<secret>
ork_live_7f3a9c21_q3Xv…   (43 URL-safe characters of secret)
```

- `env` is `live` or `test`. It is a label for you, and both kinds work the same way.
- The prefix (`ork_<env>_` plus 8 hex characters, for example `ork_live_7f3a9c21`) is stored and
  appears in key lists and audit entries.
- The server stores only the SHA-256 hash of the full token. You see the token **once**, when you
  create the key.

## Creating a key

<Tabs items={['Console', 'API']}>
<Tab value="Console">

Open **Integrations**, then **API keys**, then **New API key**. Pick a preset or choose the scopes
yourself:

| Preset | Scopes |
|---|---|
| Read only | `instances:read`, `templates:read` |
| CI/CD deploy | `instances:read`, `instances:deploy`, `templates:read` |
| ork CLI (developer) | `instances:read`, `instances:deploy`, `templates:read`, `templates:write`, `imports:write` |
| Image publishing | `applications:write` |

Copy the token right away and put it in your CI secret store.

</Tab>
<Tab value="API">

Only a signed in user (a session) can create keys. Another key cannot:

```http
POST /api/v1/api-keys
x-co-csrf: 1
Content-Type: application/json

{
  "name": "github-actions shop",
  "tenantId": "8a1c…",
  "role": "CustomerDeveloper",
  "scopes": ["instances:read", "instances:deploy", "templates:read"],
  "expiresAt": "2027-01-31T00:00:00Z",
  "environment": "live"
}
```

```json
{
  "apiKey": { "id": "…", "name": "github-actions shop", "prefix": "ork_live_7f3a9c21", "role": "CustomerDeveloper", "scopes": ["…"], "expiresAt": "2027-01-31T00:00:00.000Z", "lastUsedAt": null, "revokedAt": null },
  "token": "ork_live_7f3a9c21_…"
}
```

## Roles

| Key | `tenantId` | Allowed roles | Who can create it |
|---|---|---|---|
| Tenant key | required | `CustomerAdmin`, `CustomerDeveloper`, `CustomerViewer` | Owners and admins of that tenant, platform owners and admins |
| Organization key | omitted | `PlatformAdmin`, `PlatformOperator` | Platform owners and admins only |

The API rejects any other combination with `INVALID_KEY_ROLE`, `TENANT_REQUIRED` or
`ROLE_TOO_HIGH`.

<Callout title="Templates and catalog applications need an organization key">
  Templates and catalog applications are shared by all tenants, so only platform roles can change
  them. Creating or publishing a template (`ork template push`, or a template from an import) and
  registering or publishing application images need an organization key with the `PlatformAdmin`
  role. A tenant key can still validate templates, create imports and deploy.
</Callout>

## Scopes

| Scope | Grants (within the role) |
|---|---|
| `instances:read` | Instances, deployments and their events, logs, metrics, tenants, cloud targets, incidents, status pages |
| `instances:write` | Create and update instances, upgrade the template version |
| `instances:deploy` | Deploy, destroy, approve, cancel, retry; simulation controls |
| `templates:read` | Templates, plans, applications; template validation |
| `templates:write` | Create templates and versions, publish, clone; create a template from an import |
| `applications:write` | Register applications and publish image versions (CI intake) |
| `incidents:write` | Create incidents and post updates |
| `imports:write` | Create and read IaC imports |
| `webhooks:manage` | Manage webhook endpoints, send tests, list deliveries, redeliver |
| `audit:read` | Read the audit log (and export it, with an Enterprise license) |

When a key lacks the scope an endpoint requires, the API answers `403 API_KEY_SCOPE` and names the
required scope in `details`. An endpoint that declares no scope answers `403 API_KEY_NOT_ALLOWED`.

## Using a key

```bash
export ORK_TOKEN=ork_live_7f3a9c21_…
curl -s "$ORK_API_URL/api/v1/instances" -H "Authorization: Bearer $ORK_TOKEN"
```

Requests with a bearer token need no `x-co-csrf` header.

## Lifecycle

- **Expiry**: `expiresAt` is optional and must be in the future. An expired key gets
  `401 INVALID_API_KEY`.
- **Revocation**: call `DELETE /api/v1/api-keys/:id` (it returns `204`) or use the console. The key
  stops working at once and also gets `401 INVALID_API_KEY`.
- **Last use**: the API updates `lastUsedAt` and the client address at most once a minute.
- **Audit**: every action a key takes is recorded with `actorType = API_KEY` and
  `actorLabel = "<key name> (<prefix>)"`.

## Good practice

- Create one key per pipeline or integration, with the smallest preset that works.
- Prefer tenant keys with `CustomerDeveloper` over organization keys where the job allows it.
- Set an expiry. To rotate, create the new key first and then revoke the old one.
