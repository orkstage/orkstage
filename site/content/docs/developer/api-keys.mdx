API keys authenticate automation: CI pipelines, scripts and the `ork` CLI. A key acts with a
**role**, and **scopes** narrow what that role allows. A key never outranks its role, and keys cannot
manage keys.

## Token format

```text
ork_<env>_<prefix>_<secret>
ork_live_7f3a9c21_q3Xv…   (43 URL-safe characters of secret)
```

- `env` is `live` or `test`, a label for you; both work the same.
- `prefix` (8 hex characters) is stored and shown in lists and audit entries.
- Only the SHA-256 of the full token is stored. The token is shown **once**, at creation.

## Creating a key

<Tabs items={['Console', 'API']}>
<Tab value="Console">

Open **Integrations → API keys → New API key**. Pick a preset or choose scopes:

| Preset | Scopes |
|---|---|
| Read only | `instances:read`, `templates:read` |
| CI/CD deploy | `instances:read`, `instances:deploy`, `templates:read` |
| ork CLI (developer) | `instances:read`, `instances:deploy`, `templates:read`, `templates:write`, `imports:write` |
| Image publishing | `applications:write` |

Copy the token immediately and store it in your CI secret store.

</Tab>
<Tab value="API">

Key management needs a signed-in user (a session), not another key:

```http
POST /api/v1/api-keys
x-co-csrf: 1
Content-Type: application/json

{
  "name": "github-actions shop",
  "tenantId": "8a1c…",
  "role": "CustomerDeveloper",
  "scopes": ["instances:read", "instances:deploy", "templates:read"],
  "expiresAt": "2027-01-31T00:00:00Z",
  "environment": "live"
}
```

```json
{
  "apiKey": { "id": "…", "name": "github-actions shop", "prefix": "ork_live_7f3a9c21", "role": "CustomerDeveloper", "scopes": ["…"], "expiresAt": "2027-01-31T00:00:00.000Z", "lastUsedAt": null, "revokedAt": null },
  "token": "ork_live_7f3a9c21_…"
}
```

## Roles

| Key | `tenantId` | Allowed roles | Who can create it |
|---|---|---|---|
| Tenant key | required | `CustomerAdmin`, `CustomerDeveloper`, `CustomerViewer` | Owners and admins of that tenant, platform admins |
| Organization key | omitted | `PlatformAdmin`, `PlatformOperator` | Platform owners and admins only |

Mixing them is rejected (`INVALID_KEY_ROLE`, `TENANT_REQUIRED`, `ROLE_TOO_HIGH`).

## Scopes

| Scope | Grants (within the role) |
|---|---|
| `instances:read` | Instances, deployments and events, logs, metrics, tenants, cloud targets, incidents, status pages |
| `instances:write` | Create and update instances, upgrade the template version |
| `instances:deploy` | Deploy, destroy, approve, cancel, retry; simulation controls |
| `templates:read` | Templates, plans, applications; template validation |
| `templates:write` | Create templates and versions, publish, clone; create a template from an import |
| `applications:write` | Publish application image versions (CI intake) |
| `incidents:write` | Create incidents and post updates |
| `imports:write` | Create and read IaC imports |
| `webhooks:manage` | Manage webhook endpoints, test, deliveries, redelivery |
| `audit:read` | Read the audit log (and export it, with an Enterprise license) |

A request with a key that lacks the scope gets `403 API_KEY_SCOPE` with the required scope in
`details`. An endpoint that declares no scope answers `403 API_KEY_NOT_ALLOWED`.

## Using a key

```bash
export ORK_TOKEN=ork_live_7f3a9c21_…
curl -s "$ORK_API_URL/api/v1/instances" -H "Authorization: Bearer $ORK_TOKEN"
```

Bearer requests need no `x-co-csrf` header.

## Lifecycle

- **Expiry**: optional `expiresAt` in the future. Expired keys get `401 INVALID_API_KEY`.
- **Revocation**: `DELETE /api/v1/api-keys/:id` (204) or the console. Effective immediately.
- **Last use**: `lastUsedAt` is updated (at most every few minutes) with the client address.
- **Audit**: every action is recorded with `actorType = API_KEY` and `actorLabel = "<key name> (<prefix>)"`.

## Good practice

- One key per pipeline or integration, with the smallest preset that works.
- Prefer tenant keys with `CustomerDeveloper` over organization keys.
- Set an expiry and rotate by creating a new key before revoking the old one.
