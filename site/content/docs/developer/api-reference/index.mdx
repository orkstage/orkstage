## Authentication in the reference

The document declares two security schemes: the `co_session` cookie and an API key sent as
`Authorization: Bearer ork_…` (`apiKey`). A key works only on operations
that declare a scope, as described in [API keys](/docs/developer/api-keys/).

## Refreshing

The site never calls the API at build time. To update the reference after an API change:

```bash
# with the platform running (for example: pnpm platform:up in the platform repository)
pnpm openapi:refresh                       # saves http://localhost:4000/api/docs-json
ORKSTAGE_API_URL=https://api.example.com pnpm openapi:refresh
pnpm build                                 # regenerates these pages (prebuild step)
```

After the repositories are split, the platform's CI will publish the OpenAPI file as a release asset,
and the site will pin the version it documents.
